# HRIS Safe Import Implementation Plan

Generated by `npm run legacy:mismatch`. This plan is based on the mismatch analysis and remains non-destructive.

## Import Order

1. Map master data first: legacy `campus`, `departments`, `positions`, `salary_grade`, employment classifications, and appointment statuses.
2. Preview employee master records from `employee_profile`, enriched by `contacts`, `address`, and `government_id`.
3. Import employee master records only after duplicate review and only through an approved future migration path.
4. Preview `service_record` rows and import only high-confidence employee matches first.
5. Queue orphan, low-confidence, duplicate, overlapping, and date-problem service records for manual review.
6. Import PDS-related sections only after employee identity is confirmed.
7. Leave/service credits, payroll, loans, and document/file references should wait until target schemas and file locations are approved.

## Staging and Preview

- Keep CSV previews under `scripts/output/`; this folder is gitignored.
- Keep safe generated markdown summaries under `docs/generated/`.
- Use existing migration tracking tables later: `migration_batches` and `legacy_record_map`.
- Add normalized staging tables only in a future migration after HR approves the preview workflow.

## Rollback and Safety

- Every future import must use a batch ID.
- Store source table and source row ID for every imported row.
- Import only high-confidence matches first.
- Do not overwrite current Prime-HR data automatically.
- Do not delete current data.
- Keep all rejected, orphaned, duplicate, and date-problem rows in an issue report.
- Make rollback possible by deleting or archiving rows associated with a specific import batch.
